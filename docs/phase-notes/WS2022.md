# Windows Server 2022 Standard as the target OS — notes

Owner decision (2026-10-17): **every Rahkaran server runs Windows Server 2022 Standard.** This change makes that
the primary target across code, CI and docs. Choice made: 2022 Standard is the *supported and tested* OS, but RSM
does **not** refuse to run elsewhere — another Windows version is reported, not blocked (a read-only monitor that
stops working on an unexpected box helps nobody).

## What changed

| Area | Change |
|---|---|
| CI | The three Windows jobs (`windows`, `guide-screenshots`, `iis`) run on `windows-2022` instead of `windows-latest`, so the UI tour, PDF smoke, IIS and .NET-counter tests keep running on the servers' OS even when GitHub moves `windows-latest` to a newer image. |
| Collector | `WindowsInventoryCollector` also reads `OperatingSystemSKU` (CIM query, read-only) and emits `os.build` (from `BuildNumber`) and `os.sku`. Test: `WindowsCollectorTests` (build 20348, SKU 7). |
| Rule | **OS-019** (Info, `general`, site baseline): fires when `os.build` ≠ 20348 or `os.sku` ≠ 7 (7 = Server Standard). Both values are rule params, so they can be tuned in JSON without a rebuild. Quiet when the facts are missing (older bundles). Examples: 2019 Standard and 2022 Datacenter fire; 2022 Standard stays quiet. Row in `RULES.md` §1; it shows in the compliance table as "Windows version". |
| Manifest | `app.manifest` comment: the one `supportedOS` GUID covers Windows 10/11 and Server 2016–2022; primary target 2022 Standard. No functional change. |
| Fixtures | `lab-facts.json` gains `os.build` 20348 and `os.sku` 7 (the lab box is 2022 Standard already). |
| Docs | README (en/fa/root), ARCHITECTURE (PDF fallback, CI), PLAN (verification, P5 acceptance, Q1), handoff file. |

Not changed: target framework (`net8.0-windows`), SQL Server version rules (separate topic), `docs/SPEC.md`
(authoritative; it already lists 2019/2022 for the clean-server check, and 2022 is covered).

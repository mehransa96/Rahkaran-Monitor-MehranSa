## Decisions taken while building (please review)

1. **No SQLite in P1.** ARCHITECTURE §10 planned SQLite, but CLAUDE.md's non-negotiable rule "all SQL lives in
   embedded `Queries/**/*.sql` files executed by catalog key" (and its arch tests) does not allow RSM's own
   CREATE/INSERT statements for a local database. I did not exempt them. Snapshots are stored as files through
   `IDataFolder` instead, which is all P1 needs. **Before P5 (time series) the owner needs to decide** — see
   ARCHITECTURE §10 for the two options.
2. **Compliance table from rules.** The expected value of each compliance row is a `baseline` block in the same rule
   JSON as its threshold and source (no second copy of thresholds).
3. Four rule *behaviour* fixes found while reviewing the rendered report — listed in RULES.md "Compliance baseline".
4. Masked bundles drop raw collector payloads and site notes: those can hold names RSM does not know are sensitive.
5. Verify.Xunit 31.12.5 (MIT) added for snapshot tests; Scriban 7.5.0 for the template.

## Demo script (Windows)

1. Start `RSM.exe` (portable: empty `data` folder next to it). *Sites & Connections*: open or create the site, enter
   `Rahkaran databases` (e.g. `RahkaranDB`) or leave it empty for auto-detection, *Save*.
2. *Reports* → pick the site → *Diagnose now*. The status bar shows each collector; the summary shows critical /
   warning / info counts and the number of undecided rules. Tick *heavy checks* only off-hours (warning shown).
3. Choose *Persian report*, tick *Mask*, *Save HTML report* → copy the path from the box, open it in a browser:
   RTL, Jalali + Gregorian, compliance table (Deviation / Compliant / Unknown / Not applicable), findings with
   "general guidance — confirm with ستاد فنی" chips, appendix. Server, DB and login names appear as `SRV-1`, `DB-1`, `LOGIN-1`.
4. *Save JSON bundle* → `RSM_<site>_<time>.zip` with `manifest.json` and `snapshot.json`.
5. *SQL Server* and *Databases* pages: key facts and that layer's findings; hover a finding for its recommendation.
6. With a login lacking msdb rights: the diagnosis still completes; Agent/backup collectors show *Unavailable* with
   the reason; affected rules are listed as undecided in the report appendix — nothing crashes.

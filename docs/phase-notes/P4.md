## Safety work in this phase

- New bans (all projects): `DiagnosticsClient` dumps, profiler attach, startup hooks, environment read/write, perf
  maps, `ResumeRuntime`, every EventPipe overload except the provider-list one; diagnostic ports / router types; ETW
  `TraceEventSession`; `.etlx` writing; symbol lookups. `DiagnosticsClient` itself is banned outside `RSM.Safety`.
  Canary tests for each, plus a test that **every public `DiagnosticsClient` method is either allowed or banned**,
  so a package update that adds a command fails the build until reviewed.
- Query packs: SqlGuard profile `QueryPack` (tables/views only, no EXEC, no UDF/TVF calls, no cross-database or
  four-part names) at load **and** at run time; unknown manifest members, path traversal, oversize files and
  thresholds without a `general` / `stad-fanni:` source are refused.
- RabbitMQ stays GET-only on three paths (`RabbitGetClient`); the collector is tested to use only those paths.
- The CodeMeter port query is a constant `CimQuery` filter built from an integer PID (validated by the WQL pattern).

## Acceptance evidence

- **RESP/INFO parser and ExecutionLog aggregation unit-tested** — `RedisCollectorTests` (INFO ratios, SLOWLOG keeps
  no values, CLIENT LIST per host without RSM itself, increasing counters), `SsrsTests` (nearest-rank p50/p95, dominant
  phase, failure statuses, subscriptions). **A query pack with `UPDATE` is refused with a visible reason** —
  `QueryPackTests`: `rejected by SqlGuard: SG010-… at line 2`, shown on the Query packs page; plus cross-database,
  UDF, TVF, EXEC, DELETE, SELECT INTO, GO, linked server, UPDLOCK and #temp cases.
- **GC / thread-pool counters for an ASP.NET Core app under IIS, in-process and out-of-process** — CI Windows job:
  Hosting Bundle, `tests/integration/RsmItCoreApp` in `CoreInPool` (in-process, w3wp) and `CoreOutPool`
  (out-of-process, dotnet child of w3wp); `DotNetRuntimeLiveTests` asserts hosting model, GC heap, thread-pool
  threads, time in GC and requests for both, and the read-only proof covers both pools. Locally (Linux) the
  EventPipe reader is proven end to end against the test process itself (`RuntimeCounterReaderTests`).
- **Topology map for a 3-node lab** — `TopologyTests` models the lab (ARR farm with two App servers, Data + Redis,
  separate Report node, an unprofiled DBA laptop): ARR → app01/app02 by farm weights, SQL sessions resolved by
  host name *and* client address, Redis connections by IP, declared SSRS links, the server's own sessions not drawn;
  RK-002 measures app02 at 25 % against an ARR-weighted 50 %. **Confirmation on the real lab is still pending.**
- **RabbitMQ** against a real broker — CI service `rabbitmq:3.13-management`, `RabbitMqIntegrationTests` (collector
  facts, probe Available, wrong password → Denied).
- **Query pack under least privilege** — the documented example pack runs in the CI full diagnosis
  (`pack[example-table-sizes.top-tables].ok = true` in the Rahkaran DB).

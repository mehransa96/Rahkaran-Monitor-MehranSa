## Evidence (this environment: Linux container, .NET SDK 8.0.426 Microsoft build)

- `dotnet build RSM.sln -c Release --no-incremental` → **0 warnings, 0 errors** (WPF compiled with `EnableWindowsTargeting`).
- `dotnet test RSM.sln -c Release` → **439 passed, 0 failed, 2 skipped** (the SQL integration test needs `RSM_IT_SQL`; the
  Redis one was additionally run, see below):
  - `RSM.Safety.Tests` 324 — 90 malicious SQL cases rejected with the expected rule (and again after the hardening
    prefix), 15 allowed read-only shapes, `SqlCatalogIsReadOnly` for every embedded file, 28 rejected Redis commands
    incl. CRLF injection, RESP limits, RabbitMQ path whitelist, data-folder escapes, log redaction end-to-end.
  - `RSM.Tests` 65 — expression language (incl. regex timeout, no code execution), rules engine (JSON fixtures),
    scheduler, profile/secret stores, resource completeness (fa/en keys, placeholders, no XAML literals), every catalog
    key documented in `SQL_CATALOG.md`.
  - `RSM.ArchTests` 49 — dependency rules, no RS0030 suppression, analyzer present in every project, single safety
    boundary, no SQL literals in C#, no server-action commands, and the **real BannedApiAnalyzer run in-process** on 21
    banned snippets plus a check that every banned entry resolves to a real API when its type is available.
- `./build/analyzer-canary.sh` → "analyzer canary: OK (build failed with RS0030 as required)".
- Redis integration against a local `redis-server` with a password → passed; Redis `INFO commandstats` afterwards
  listed only `auth`, `ping`, `info`, `slowlog|len`, `client|list` (plus `dbsize` from the manual check).
- `dotnet publish src/RSM.App -c Release -r win-x64` → `RSM.exe` 162 MB self-contained single file +
  `Fonts/OFL-Vazirmatn.txt`.

## Demo script (Windows)

1. Copy `RSM.exe` to a folder, create an empty `data` folder next to it (portable mode), start it.
2. The UI opens in Persian (RTL). *تنظیمات* → English: layout flips to LTR instantly; switch back.
3. *Sites & Connections* → *New site*, server `DB01`, host `<sql host>`, roles Data + Report, SQL login
   `rsm_monitor` + password, *Trust server certificate* if the server uses a self-signed cert (warning shown).
4. *Test connection* → Capability Matrix: connect, VIEW SERVER STATE, VIEW ANY DEFINITION, databases, msdb, Agent
   available; error log / SSRS show the reason and the PERMISSIONS.md section if not granted; Windows/IIS rows say
   "arrives in a later phase". Try a sysadmin login to see the high-privilege banner.
5. *Save*, restart RSM: the site is back; `data/sites/*.json` is readable JSON without passwords; the password is in
   `data/secrets/*.bin` (DPAPI). `data/logs/rsm-*.log` contains no password.

# پایشگر سرور راهکاران (RSM)

ابزاری قابل‌حمل و **کاملاً فقط‌خواندنی** برای ویندوز که کارشناس پشتیبانی روی سرورهای راهکاران مشتری (یا از راه دور)
اجرا می‌کند تا سلامت SQL Server، پایگاه‌های داده، ویندوز، IIS/ARR، Redis، SSRS و سرویس‌ها را ببیند، علت کندی را
پیدا کند و گزارش عیب‌یابی فارسی یا انگلیسی تهیه کند.

**وضعیت: فاز ۵ (همهٔ امکانات: پایش زنده، تاریخچه و خط مبنا، دستیار کندی، گزارش‌ها شامل PDF، ورود بسته‌ها و CLI).** سایت و سرورها را تعریف کنید، با «آزمون اتصال» ماتریس قابلیت‌ها را
ببینید و در «گزارش‌ها» با «عیب‌یابی» یک بررسی فقط‌خواندنی از SQL Server، پایگاه‌های داده و ویندوز در مقایسه با توصیه‌های
ستاد فنی بگیرید (گزارش HTML فارسی یا انگلیسی، بستهٔ JSON، پوشاندن اختیاری نام‌ها). با «اتصال نمای زنده» در صفحه‌های
نمای کلی، SQL Server، کوئری‌ها و Blocking یا ویندوز، سرورها لحظه‌ای پایش می‌شوند: CPU (‏SQL در برابر سایر فرایندها)،
انتظارها، شمارنده‌ها، تأخیر فایل و دیسک، زنجیرهٔ Blocking با سرِ زنجیره، تراکنش‌های باز، Deadlockها از system_health،
پرس‌وجوهای پرهزینه با هشدارهای Plan، پسرفت‌های Query Store، حافظه، دیسک، شبکه و فرایندهای پرمصرف — با نمودارهای ۱۵/۳۰/۶۰
دقیقه‌ای، خطوط آستانه، توقف موقت (خودکار هنگام کوچک‌کردن پنجره) و نمایش سربار خود RSM. صفحهٔ IIS سایت‌ها، Application
Poolها، Worker processها، درخواست‌های در حال اجرا در همین لحظه، صدک‌های زمان پاسخ هر آدرس از لاگ W3C، خطاهای HTTP.sys،
web.config با پوشاندن مقادیر محرمانه و گواهی‌ها را نشان می‌دهد؛ صفحهٔ ARR فارم‌ها و قوانین URL Rewrite (از جمله «تغییر مسیر
برنامه پس از به‌روزرسانی») را؛ صفحهٔ سرویس‌ها فقط وضعیت سرویس‌ها را نمایش می‌دهد؛ و «خطاها و رخدادها» رخدادهای SQL، ویندوز و
IIS را روی یک خط زمانی با همبستگی ±۵ دقیقه و پایگاه دانش فارسی/انگلیسی می‌آورد. فاز ۴ این‌ها را اضافه می‌کند: Redis
(INFO، فرمان‌های کند، تأخیر، اتصال هر سرور برنامه)، SSRS (گزارش‌های کند با تفکیک داده و رندر، خطاها، اشتراک‌ها)، RabbitMQ
(فقط درخواست GET به API مدیریتی: هشدارها و صف‌های گیرکرده) و CodeMeter (سرویس و پورت)، نقشهٔ توپولوژی کشف‌شده از فارم‌های
ARR، نشست‌های SQL و کلاینت‌های Redis، شمارنده‌های اختیاری زمان اجرای .NET برای Poolهای راهکاران (EventPipe، محلی، به‌طور
پیش‌فرض خاموش) و بسته‌های کوئری تیم که پیش از اجرا با SqlGuard بررسی می‌شوند.

فاز ۵ دستیار **«چرا راهکاران کند است؟»** را اضافه می‌کند: ضبط هم‌زمان همهٔ گره‌ها با آهنگ سریع‌تر و فقط‌خواندنی به مدت
۱۲۰ ثانیه، سپس علت‌های رتبه‌بندی‌شده با شواهد، خط زمانی مشترک و گام‌های بعدی فقط متنی. همچنین اضافه می‌کند:

- **تاریخچهٔ** محلی با **خط مبنای** ساعت-هفته، هشدار ناهنجاری در نمای زنده و مقایسهٔ بازه‌ها؛
- گزارش **PDF** که آفلاین با WebView2 چاپ می‌شود؛
- **ورود و ادغام** بسته‌های چند ماشین یک سایت؛
- **`RSM.Cli`** برای اجرای بدون رابط.

راهنمای کاربر: [`docs/user-guide/README.fa.md`](docs/user-guide/README.fa.md).

## فقط‌خواندنی از پایه

RSM نمی‌تواند روی هیچ سروری چیزی را تغییر دهد، راه‌اندازی مجدد کند یا دستوری اجرا کند:

- همه دستورات T-SQL در فایل‌های کاتالوگ داخل برنامه هستند و پیش از اجرا از **SqlGuard** (تحلیل درخت نحوی ScriptDom)
  عبور می‌کنند؛ هیچ متن SQL در کد C# ساخته نمی‌شود و ویرایشگر SQL وجود ندارد؛
- APIهای خطرناک ‎.NET (اجرای فرایند، کنترل سرویس، ذخیره پیکربندی/Recycle در IIS، متدهای WMI، نوشتن در رجیستری و
  Event Log، حذف فایل، Socket/HTTP مستقیم و …) در زمان کامپایل **خطا** هستند؛
- اتصال به Redis و RabbitMQ فقط از طریق کلاینت‌هایی است که فهرست ثابتی از دستورات خواندنی را ارسال می‌کنند؛
- در رابط کاربری هیچ دکمه‌ای برای Kill، Recycle، Restart، Shrink یا Rebuild وجود ندارد؛ توصیه‌ها فقط متنی هستند؛
- بدون دسترسی به اینترنت، بدون ارسال داده و بدون به‌روزرسانی خودکار.

از حساب‌های کم‌دسترسی شرح‌داده‌شده در [`PERMISSIONS.md`](PERMISSIONS.md) استفاده کنید.

## اجرا

۱. فایل `RSM.exe` را از خروجی CI (یا ساخت محلی) در هر پوشه‌ای کپی کنید؛ نصب لازم نیست.
۲. حالت قابل‌حمل (اختیاری): کنار `RSM.exe` پوشه‌ای به نام `data` بسازید یا برنامه را با `--portable` اجرا کنید؛
   در غیر این صورت داده‌ها در `%LOCALAPPDATA%\RSM` ذخیره می‌شوند.
۳. «سایت‌ها و اتصال‌ها» ← «سایت جدید» ← افزودن سرور ← «آزمون اتصال».
۴. برای امکانات IIS، برنامه را روی همان سرور با «Run as administrator» اجرا کنید (RSM هرگز خودش دسترسی بالا نمی‌گیرد).

رمزها فقط با DPAPI ویندوز برای همان کاربر ذخیره می‌شوند یا اصلاً ذخیره نمی‌شوند.
